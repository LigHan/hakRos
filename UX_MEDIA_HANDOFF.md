## Результат

- Один нижний островок находится в корневом layout и сохраняет позицию при открытии «+», редактора и публикации. Меню анимируется только при появлении; при закрытии сразу удаляется из дерева, чтобы остановленная браузером анимация не оставляла страницу поверх другого экрана.
- Рисованный режим: исправлены метрики Caveat, переносы заголовков, контуры карточек и компактный веб-контейнер. Рамки не выходят за границы узких карточек.
- Возврат к рекомендациям обновляет данные без замены списка экраном загрузки. Смена аккаунта очищает прежнюю приватную ленту, а устаревший ответ запроса не восстанавливает её после выхода.
- Карточка рекомендации открывает `/place-post/[id]`, социальный пост — `/post/[id]`. Профиль автора/заведения открывается отдельным действием.
- В мобильном приложении доступна запись видео: история до 60 секунд, запись поста до 120 секунд. Пост поддерживает выбор готового MP4/MOV/WebM на телефоне и компьютере. Лимит файла — 25 МиБ. Истории создаются только в приложении iOS/Android, включая блокировку прямого веб-адреса редактора истории.
- Файлы загружаются на API и сохраняются в SQLite; локальный `file://` не публикуется как общий адрес. Поддержаны повторная отправка, предварительный просмотр, отмена и ошибки разрешений/сети. Текстовые черновики сохраняются локально; незагруженное видео нужно выбрать повторно после закрытия редактора.
- Настройки аккаунта: био до 500 символов, выбор/удаление JPEG-аватара до 1 МиБ после обработки, приватность профиля. Настройки сохраняет сервер и получает профиль после повторного открытия. Имя и аватарка остаются видимыми, приватные био и материалы доступны владельцу и подтверждённым друзьям. Приватный режим по умолчанию сохраняет существующие правила доступа; открытый профиль включается явно. У компаний остаются правила подписок на заведения.

## Контракт и общие файлы

- `GET/PATCH /api/account/profile`, `GET /api/profiles/:id`, `GET /api/profile-avatars/:id/:version`: модуль `backend/account-profile.js`, отдельная таблица `account_profiles`.
- `POST /api/media`: Bearer-авторизация, бинарное тело и настоящий MIME в Content-Type. Ответ `{id,url,kind,mimeType}`. При публикации передать `mediaId`.
- `GET /api/media/:id`: авторизованное чтение, Range 206/416. Для браузерного проигрывателя выдаются зашифрованные ссылки на 15 минут, привязанные к действующей сессии. Каждое чтение заново проверяет права на материал, срок истории, дружбу и приватность. После выхода или перезапуска API ссылка недействительна. Обновление публикации получает новую ссылку.
- В `social_items` добавляется `media_id`; существующие строки сохраняются. Сама публикация, реакции, комментарии, репост и медиа применяют общие правила видимости.
- Профиль и медиа подключены до общего JSON-parser в `backend/server.js`, профиль инициализируется перед social. CORS поддерживает PATCH.
- Добавлены совместимые пакеты `expo-video ~58.0.14`, `expo-file-system ~58.0.13`. Камера, микрофон и фото настроены через plugin `expo-image-picker` в `frontend/app.json`.

## Запуск

Для обычной установки используйте Node.js 24 LTS. В `backend` и `frontend` отдельно выполните `npm ci`. Далее запустите API через `npm start` в backend и `npm run web` в frontend. Параметры адреса сервера — в README.

Для локальной проверки API запускался на `http://127.0.0.1:3120`, интерфейс — `http://localhost:8105`. Использовалась отдельная база вне репозитория, настоящие пользовательские базы не изменялись. Учётные записи локального деморежима описаны в STATISTICS.md.

Для телефона используйте общий доступный API без `LOCAL_DEMO`, корректный сетевой `EXPO_PUBLIC_API_URL` и совместимое приложение Expo Go или development build. Существующую development build пересоберите, чтобы применились разрешения камеры и микрофона. Кодек должен поддерживаться устройством; для совместимости предпочтителен MP4 H.264/AAC.
