# Статистика и локальная интеграция

Эта ветка содержит локальную интеграцию статистики в приложение на основе `main` (`a40285a`). Код предназначен для проверки и дальнейшей работы команды, а не для публикации как готового сервиса. Интерфейсы и изменения общих файлов необходимо согласовать с владельцами Т-01, Т-05, Т-07 и Т-08.

## Запуск на другом компьютере

Потребуются Git, Node.js 24 LTS и npm. В отдельной папке:

```bash
git clone --branch task/stats-local-integration https://github.com/LigHan/hakRos.git
cd hakRos/backend
npm ci
```

В PowerShell для запуска API в режиме локальной демонстрации:

```powershell
$env:LOCAL_DEMO = '1'
$env:HOST = '127.0.0.1'
npm start
```

Во втором терминале из корня репозитория:

```powershell
cd frontend
npm ci
npm run web
```

Откройте адрес из вывода Expo, обычно `http://localhost:8081`. Если запуск Expo возвращает ошибку сетевого запроса, можно попробовать `npx expo start --web --offline`. Проверка веб-сборки зависит от доступности ранее установленных зависимостей.

При включённом `LOCAL_DEMO=1` локально создаются два тестовых аккаунта: `user@local.test` и `company@local.test`; вход `admin@local.test` доступен только в этом режиме. Для всех пароль `demo1234`. Это публичные демонстрационные данные, они не годятся для настоящих пользователей. Режим демо отказывается слушать сетевые интерфейсы: он работает только с `127.0.0.1`, `localhost` или `::1`. Без `LOCAL_DEMO` тестовый администратор и начальное назначение места компании не включаются.

Откройте «Профиль», войдите как пользователь, выполните действия и выберите «Открыть статистику». У тестовой компании закреплено первое место в БД — в стандартном наборе это «Парк Щербакова». Для сравнения выйдите и войдите как компания или администратор. У каждого участника своя локальная база: действия на одном компьютере не появятся на другом. Локальные базы и `.env` не публикуйте.

## Локальная панель администратора

При входе как `admin@local.test` в вебе открывается полноэкранная тёмная панель с общей статистикой, местами и пользователями. Для места можно изменить название, описание, адрес и категорию; категории соответствуют фильтрам приложения. Для записей в таблице `users` можно просмотреть и изменить имя, фамилию и email. Роль показана только для чтения; пароли и их хеши не выводятся и не изменяются. Демо-администратор задан отдельно от таблицы `users`, поэтому в этом списке отсутствует.

Переход «Перейти на сайт» сохраняет сессию и открывает обычную ленту. В вебе администратор может удалить публикацию или отзыв из ленты и карточки; возврат в панель — через профиль. Удаление публикации также удаляет её отзывы, истории и данные карточки. Уже записанные события статистики остаются; связь места с компанией сохраняется для её исторических показателей. Рейтинг места пока хранится отдельно и после удаления отзыва не пересчитывается.

На Android вход администратора ведёт в обычный профиль, административные кнопки не показываются, а экран статистики запрашивает только его личные события. Это ограничение интерфейса: серверная сессия всё равно имеет роль `admin`, поэтому для настоящего сетевого сервиса необходимо отдельно спроектировать права и защищённый вход. Существующий локальный деморежим слушает только localhost.

После перезапуска API сессии сбрасываются: если админ-панель сообщает, что требуется вход, нажмите «Войти в аккаунт» и авторизуйтесь снова. Ошибка доступа обычного пользователя не предоставляет административные данные.

Изменения структуры: `frontend/app/admin.tsx` содержит панель, а корневой `_layout.tsx` раскрывает её на всю ширину веба. `backend/admin.js` содержит `GET /api/admin/places`, `PUT` и `DELETE /api/admin/places/:id`, `DELETE /api/admin/reviews/:id`, `GET /api/admin/users` и `PUT /api/admin/users/:id`. В `backend/server.js` модуль подключён к API; `backend/statistics.js` предоставляет ему проверку общей серверной сессии и поддерживает `?scope=personal` для личной статистики администратора. Каждый административный маршрут требует токен администратора и включён только в `LOCAL_DEMO=1`. Регистрация не позволяет занять email демо-администратора.

Эти изменения — локальная интеграция по согласованию пользователя. Перед объединением пункту 5 необходимо сверить маршруты, авторизацию, категории и общие файлы с владельцами Т-01, Т-05, Т-06, Т-07 и Т-08. При изменении email тестовых пользователя или компании демозаполнение при следующем запуске может вновь создать запись с исходным тестовым email; компания снова будет привязана к первому месту. Открытые сессии сохраняют прежние данные профиля до нового входа.

## Что считает система

За последние 30 дней выводятся:

- Поиски по тексту и поиски без результатов: событие после 800 мс без изменения введённого запроса, если список успешно загружен. Поиск без результатов записывается дополнительно к общему поиску.
- Просмотры карточек и их категории, получаемые с сервера по идентификатору места.
- Добавления лайков и в избранное; снятие лайка или удаление из избранного не вычитается из счётчика действий.
- Запросы маршрута и нажатия «Поделиться»; последнее означает попытку и не подтверждает отправку.

События записываются только при наличии авторизованной сессии; неавторизованные действия не учитываются. Ошибка отправки события не прерывает действия пользователя. Итоговые числа — количество событий, не количество уникальных людей или текущее число лайков. Есть локальная фильтрация по трём ролям: пользователь видит свои действия, компания — события мест из таблицы владения, администратор — общие данные. Сервер получает идентификатор пользователя из сессии, категорию — из места в БД; роль клиента не используется для авторизации.

## Важные ограничения

- Сессии — локальные токены в памяти сервера с ограничением 12 часов; после перезапуска требуется войти снова. Клиент хранит токен в AsyncStorage, что требует пересмотра до рабочего развёртывания.
- Вход через Yandex/VK и восстановление пароля пока не реализованы; кнопки присутствуют в старом интерфейсе. Создание публикаций и историй остаётся запланированной задачей команды. Они не проверяются тестами статистики и админки.
- Администратор и привязка тестовой компании к месту реализованы только для локального демо. Для реальной работы нужны безопасная выдача администраторских прав и управление владением местами.
- События и связи находятся в SQLite текущего сервера. Срок хранения, удаление персональных идентификаторов, обработку повторов и согласованный контракт событий ещё предстоит определить. Историю из тестовой базы не переносить автоматически.
- Лайки и избранное приложения всё ещё хранятся на устройстве; статистика фиксирует действия и не синхронизирует текущее состояние между устройствами.
- Тесты проверяют API и фильтрацию, а не работу всей навигации на телефоне. Подбор по времени и бюджету в рамках этой ветки не реализован. Если удалить все места, демонстрационное заполнение восстановит их при следующем запуске базы.
- Проверку прав и защиту сервиса необходимо пересмотреть до совместного использования по сети. Не используйте локальный деморежим с настоящими данными.

## Проверки

В `backend`:

```bash
node --test admin.local.test.js integration.local.test.js
```

Тесты запускают сервер с базой в памяти и проверяют роли, доступ без токена, фильтрацию статистики, запись событий, выход и административное редактирование с проверкой прав. Во `frontend`:

```bash
npm run typecheck
npm run lint
```

11.11.2026 проверки выше и экспорт Web и Android прошли на Windows с Node.js 24.19.0. В браузере проверены вход и выход, запрос нового входа при отсутствии сессии, запрет админки для обычного пользователя, поиск пользователей, переход на сайт и увеличение счётчика просмотра. Административное удаление и сохранение статистики проверены API-тестом на временной базе. Физическое Android-устройство не проверено.
