# Зависимости старого проекта и установка

Снимок изучен в [LigHan/paths, коммит e1f4863](https://github.com/LigHan/paths/tree/e1f4863be60abbace48c0c98c806e86bb17ff43c). Это **зависимости старого приложения**, не доказательство работоспособности нового: его исходный код ещё не перенесён, установка и запуск не проверены. При переносе Т-01 сверяет файлы, версии и инструкции с фактическим состоянием и обновляет этот документ. Новые зависимости добавляются только после согласования.

## Что понадобится

- Git и GitHub CLI — для доступа к репозиторию; настройка описана в `PROJECT_PROGRESS.md`.
- Node.js и npm — для frontend и backend. В просмотренных корневых манифестах минимальная версия Node.js не задана; совместимую версию нужно проверить по перенесённому lock-файлу, инструментам и фактическому запуску. Не считайте произвольную версию Node подтверждённой.
- Доступ к npm и необходимые средства платформы для установки нативных пакетов; в backend используется `sqlite3` и `bcrypt`. Возможные системные требования и мобильные инструменты зависят от ОС и среды и должны быть проверены при установке.
- Для демонстрации мобильной версии потребуется подходящая среда запуска Expo: браузер, устройство или эмулятор в зависимости от выбранной платформы. Доступность конкретного способа пока не проверена.

## Установка и запуск после переноса

В новом репозитории пока нет `frontend/` и `backend/`: команды ниже будут применимы **только после переноса соответствующих папок вместе с их `package.json` и `package-lock.json`**. Из корня проекта, в отдельных терминалах:

```powershell
cd backend
npm ci
npm start
```

```powershell
cd frontend
npm ci
npm start
```

`npm ci` устанавливает зависимости по соответствующему lock-файлу; если lock-файл не перенесён, не совпадает с манифестом или установка завершилась ошибкой, сначала выясните причину вместе с Т-01. Не заменяйте автоматически lock-файл, не добавляйте `node_modules` в Git. В старом backend также есть `npm run dev`, а во frontend — `npm run android`, `npm run ios`, `npm run web`, `npm run lint`. Эти команды взяты из манифестов; их успешность и настройки подключения не проверялись.

В старом репозитории присутствует `backend/.env`: **не переносить его автоматически** и не публиковать значения. Т-01 проверяет, какие переменные действительно нужны, создаёт безопасный пример без секретов и согласовывает локальную настройку. Реальные базы данных также не копировать без проверки их содержимого и разрешения.

## Проверка после переноса

Т-01 должен записать в `PROJECT_PROGRESS.md`: версии Node.js/npm и платформу, результат обеих установок, реальные команды запуска, требуемые переменные без значений, доступные адреса сервисов и результат проверки основного сценария. Если есть несовместимость пакетов, сначала воспроизвести её и согласовать изменение манифеста/lock-файла; не обновлять зависимости массово без необходимости.
