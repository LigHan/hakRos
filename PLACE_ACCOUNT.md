# Т-06. Кабинет заведения

Войдите в аккаунт компании и откройте **Профиль → Управлять заведениями**. Здесь можно создать карточку или изменить уже привязанное заведение. В карточке редактируются название, адрес, описание, категория, фото и часы работы. Пока адрес вводится вручную. Подсказки улиц и выбор точки на карте запланированы в [Т-19](TASKS.md#т-19--адрес-заведения-после-подключения-карты).

Нажмите «Выбрать фото», чтобы загрузить изображение с устройства и увидеть его в форме. Можно заменить или убрать фото. Изменения применяются при сохранении карточки.

В разделе «Часы работы» нажмите на существующую строку или «Добавить часы». Выберите дни недели и укажите время открытия и закрытия. Для ночного графика выберите более раннее время закрытия, и оно будет относиться к следующему дню. Также доступны режимы «Круглосуточно» и «Закрыто». Нажмите «Применить», чтобы добавить строку в форму, затем сохраните карточку.

После сохранения нажмите «Открыть карточку», чтобы проверить публичный вид. Новый аккаунт компании получает своё первое заведение при создании карточки. В локальном деморежиме тестовой компании уже привязан парк Щербакова.

## API

Маршруты используют токен компании из `POST /login`. При создании владелец берётся из серверной сессии. Кабинет и статистика используют существующие связи из `local_place_owners`.

| Метод и путь | Результат |
|---|---|
| `GET /api/company/places` | Карточки текущей компании |
| `GET /api/company/places/:placeId` | Своя карточка |
| `POST /api/company/places` | Создать и привязать карточку |
| `PUT /api/company/places/:placeId` | Сохранить свою карточку |

Основные поля запроса — `place`, `address`, `bio`, `category` и `workingHours`. Расписание передаётся как `[{ label, value }]`. Пустой массив очищает расписание. Загружаемое фото передаётся в `coverBase64` как JPEG до 1 МиБ после обработки. Файл сохраняется в SQLite и доступен по относительному адресу из `image`. Пустое значение `image` удаляет фото. Если оба поля опущены при редактировании, текущее фото сохраняется. Для существующих клиентов `image` по-прежнему принимает ссылки HTTP(S). При повторной отправке создания интерфейс использует тот же `requestId`, поэтому повторный запрос возвращает ту же карточку.

Публичный маршрут `GET /api/posts/:id` возвращает сохранённые данные. Запуск проверки из `backend` — `node --test company-places.local.test.js`.
