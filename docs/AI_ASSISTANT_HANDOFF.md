# ИИ-помощник: подключение и передача команде

Помощник встроен в основное приложение: маскот находится над общей нижней панелью, а чат обращается к основному API `/api/assistant`. Доступ разрешён только вошедшим: гость при нажатии переходит ко входу, API проверяет серверную сессию. Карточки, планы и приглашения подключены; сведения о стоимости заполняются для каждого места администратором и без источника не считаются подтверждёнными.

При удержании маскот увеличивается и подсвечивается; его можно двигать по горизонтали и немного вверх, после отпускания он возвращается к панели. Две стартовые фразы — «Есть пара часов» и «Подскажи, куда сходить». Дизайнер может менять оформление компонента `frontend/components/assistant/AssistantLauncher.tsx`; его подключение находится в `frontend/components/floating-navigation.tsx`. `/assistant-preview` остаётся отдельным примером, его нижняя панель декоративная. Дизайн и поведение на физических устройствах требуют совместной проверки.

## Настройка

1. Запустить основной backend и frontend по [README](../README.md), войти в аккаунт приложения. Отдельный сервер помощника больше не нужен. Адрес API задаётся обычным `EXPO_PUBLIC_API_URL`, как и для остальных функций приложения.
2. Для ответов GigaChat серверу нужен `GIGACHAT_AUTH_KEY` — Authorization Key из проекта Сбера; необязательный `GIGACHAT_MODEL` по умолчанию `GigaChat-2-Max`. Хранить ключ только в окружении backend или локальном `backend/.env`, исключённом из Git. Не помещать ключ в `EXPO_PUBLIC_*`, frontend, переписку или документацию. Ранее отправленный в чат ключ следует перевыпустить.
3. Установить или предоставить процессу официальные сертификаты Минцифры согласно [документации GigaChat](https://developers.sber.ru/docs/ru/gigachat/certificates). Если используется файл с доверенным CA, задать `NODE_EXTRA_CA_CERTS` **до запуска Node.js**. Не отключать проверку TLS.
4. Перезапустить backend после настройки. Признак `configured` означает наличие настройки, а не успешную связь с провайдером; проверьте ответ через чат. Без ключа или при сетевой ошибке помощник сообщает о недоступности и сохраняет текст для повторной отправки.

Помощник передаёт GigaChat сообщения и разрешённую справку о текущем экране, но не данные мест или личные сведения профиля. Модель возвращает структурированное намерение, а сервер проверяет параметры и выбирает до трёх карточек из общей таблицы мест по категории, словам интереса, известным расходам и рейтингу. Вопросы об адресе и сравнении расходов разрешаются по данным каталога; при неоднозначности нужно уточнение. Новая база содержит демонстрационные места и не содержит проверенных цен. Длительность, часы работы и расстояние не проверяются. Данные заведения не становятся инструкциями модели.

## Контракт

Оба запроса требуют заголовок `Authorization: Bearer <токен-сессии>`; без действительной сессии — HTTP 401. Токен приложения не передаётся в GigaChat.

- `GET /api/assistant/health` → `{ "mode": "gigachat", "configured": true | false }`.
- `POST /api/assistant/chat` принимает `{ "message": "...", "history": [...], "context": { "screen": "home", "placeId": "...", "shownPlaceIds": [], "preferences": { "budget": 500, "currency": "RUB", "durationMinutes": 120 } }, "excludePlaceIds": [] }`: сообщение до 1000 символов, история до 20 сообщений ролей `user`/`assistant`, каждое до 1000 символов. Экран и ID проверяются сервером; бюджет и длительность в контексте предназначены только для продолжения диалога.
- Успех: `{ "reply": "...", "mode": "gigachat", "catalogAvailable": true | false, "parameters": {...}, "cards": [...] }`. Карточка содержит ID, название, адрес, изображение, причину и разрешённые действия; неизвестные стоимость и длительность равны `null`. Ошибки проверки — HTTP 400, ограничение частоты или параллельного запроса — HTTP 429, недоступный провайдер — HTTP 503.

История хранится в состоянии интерфейса. Ключ, сессии, приватные профили, описания мест и отзывы автоматически в модель не передаются; при этом пользователь может сам написать личные сведения в сообщении, которое отправится провайдеру. Действует локальное ограничение на аккаунт: не больше 20 запросов в минуту и одного одновременного. Оно хранится в памяти одного процесса и не является распределённой защитой; перед публикацией сервера в интернет нужны общий лимит расходов, согласованный CORS, хранение секретов и политика работы с данными.

## Стоимость и карта

В локальной админке «Места → Редактировать» отдельно сохраняются тип и цена входа, примерные расходы внутри, источник и время обновления. Значение `null` означает неизвестность, а бесплатный вход не означает отсутствие других расходов. Подбор отмечает соответствие бюджету только при известных входе и верхней оценке расходов. Источник необходимо проверить и обновлять; модель цены не придумывает.

Кнопка «Привязать точку» в админке связывает существующую опубликованную точку с карточкой после выбора и подтверждения. При маршруте связанная точка используется по `postId`; похожая несвязанная точка предлагается только для ручной проверки, иначе работает поиск адреса. Объекты, нарисованные на подложке карты, сами по себе не являются точками приложения и автоматически к карточкам не привязываются.

## Планы и приглашения

`/api/plans` доступен только личным аккаунтам. Создание и изменение требуют подтверждённых данных, действительного ID места, даты с часовым поясом и явного `confirmed: true`; создание также требует `requestId` для безопасного повтора. План не создаётся моделью. `GET /api/plans` показывает собственные планы и приглашения, а `GET /api/plans/:id` — только доступный план.

Организатор отправляет приглашение через `POST /api/plans/:id/invitations`, указав ID подтверждённого друга, текущую `revision` и подтверждение. Получатель отвечает через `POST /api/plans/:id/respond` с `accepted` или `declined`, подтверждением и той же версией. Повтор одного приглашения не создаёт дубликатов. Изменение времени или места возвращает принявших в состояние ожидания, а старое подтверждение другой версии отклоняется. Отмена встречи и приглашения выполняется отдельными подтверждёнными запросами. При удалении дружбы доступ отзывается.

Экран «Планы и приглашения» доступен в профиле; план можно создать из карточки места и карточки помощника. Веб-обмен показывает текст для копирования, системный обмен используется, когда доступен; непроверенная публичная ссылка не создаётся. Маршрут открывает существующую карту, а начальную точку пользователь выбирает сам. Геокодер может не распознать адрес или определить его неточно; точку нужно проверить. Входящие приглашения сейчас видны на экране планов, push-уведомлений нет. Повторно пригласить друга после отказа или отмены в тот же план пока нельзя.

Проверки: `node --test assistant/assistant.test.js tests/leisure-plans.test.js` из `backend`, `npm run typecheck` и `npm run lint -- --no-cache` из `frontend`; отдельно проверить реальный ключ, гостя, действующую и истёкшую сессию, обработку ошибок и физические устройства.

## Дальнейшая работа с командой

- Пункт 1 — согласовать API поиска и подтверждённые цену и длительность. Неизвестная цена — `null`, бесплатное — `0` только при подтверждении.
- Пункт 2 — согласовать карточки и переход к месту по проверенному ID.
- Карта — определить права на координаты, согласие пользователя и расчёт расстояния.
- Пункт 3 — согласовать доступ к группам и будущий поиск компании; не раскрывать приватные данные и не отправлять приглашения автоматически.
- Пункт 4 — минимальные события без текста диалогов; сбой аналитики не должен ломать чат.
- Пункт 5 — проверить интеграцию и обновить общий журнал по результатам команды.

Подробные этапы и критерии готовности — в [AI_ASSISTANT_PLAN.md](AI_ASSISTANT_PLAN.md).
