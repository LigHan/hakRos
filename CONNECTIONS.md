# Т-10. Друзья и подписки на заведения

В личном профиле откройте «Друзья». Найдите человека по имени или ID и отправьте заявку. Дружба появляется в обоих списках после того, как получатель нажмёт «Принять». Входящую заявку можно отклонить, исходящую — отменить. Удаление друга убирает связь у обоих участников.

Из карточки заведения можно подписаться и отписаться. Актуальный список открывается в профиле в разделе «Подписки на заведения».

## API

Запросы требуют токен личного аккаунта из `POST /login` в заголовке `Authorization: Bearer …`. После перезапуска сервера нужен новый вход. Сами дружбы и подписки сохраняются в SQLite.

| Метод и путь | Результат |
|---|---|
| `GET /api/connections` | ID текущего пользователя, друзья, входящие и исходящие заявки, подписки |
| `GET /api/connections/users?q=имя` | Поиск по имени или ID. До 20 результатов с полями `id` и `name` |
| `PUT /api/connections/friends/:friendId/request` | Отправить заявку |
| `PUT /api/connections/friends/:friendId/accept` | Принять входящую заявку |
| `DELETE /api/connections/friends/:friendId` | Отклонить, отменить или удалить связь |
| `GET /api/connections/places/:placeId` | Получить `{ subscribed: boolean }` для карточки |
| `PUT /api/connections/places/:placeId` | Подписаться |
| `DELETE /api/connections/places/:placeId` | Отписаться |

Все идентификаторы в ответах — строки. У `friends`, `incomingRequests` и `outgoingRequests` элементы имеют форму `{ id, name }`. У `subscriptions` — `{ placeId, name, handle, avatar, description }`.

## Подключение лент и карты

Во фронтенде используйте `getConnections()` из `frontend/lib/connections.ts`. На сервере модуль `backend/connections.js` предоставляет `listForUser(userId)`. Передавайте туда ID из проверенной сессии.

- Для публикаций и историй друзей берите ID из `friends`. В Т-13 согласуйте поле с ID автора материала.
- Для материалов заведений берите `subscriptions[].placeId`. У существующих историй соответствующее поле — `story.postId`. У существующих карточек — `post.id`. В новых публикациях заведений передавайте ID карточки отдельным полем.
- Для выделения мест на карте используйте те же `placeId`. Карточки с одинаковым именем автора или `userHandle` могут относиться к разным заведениям.
- Загружайте связи при открытии или обновлении экрана. Доступ к приватным материалам проверяйте на сервере по подтверждённой дружбе и правилам публикации.

## Геопозиция друзей (Т-17)

Вызов `POST /api/map/location` с `{ recipientIds: string[] }` открывает показ и возвращает его `id`. Получателями могут быть только выбранные подтверждённые друзья. `PUT /api/map/location/:id` обновляет координаты активного показа, а `DELETE /api/map/location/:id` завершает его.

`GET /api/map/locations` возвращает доступные отметки с округлёнными до трёх знаков координатами и оставшимся временем показа в `expiresInMs`. Поле `avatar` содержит относительный адрес фото из настроек профиля или `null`. Старое фото из ветки карты переносится с ограниченной видимостью и возвращается как JPEG data URL владельцу и выбранным получателям геопозиции. Отметки хранятся в памяти API до отключения, выхода из аккаунта или истечения пяти минут без обновления. При удалении дружбы показ этому человеку прекращается.

## Проверка

Из `backend` выполните `node --test connections.local.test.js`. Тест проверяет заявки с двух аккаунтов, повторные запросы, фильтрацию существующих историй по подпискам и сохранение связей после перезапуска.
