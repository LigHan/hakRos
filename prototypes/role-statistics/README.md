# Админка и статистика: прототип для команды

Направления: Т-07 (экран статистики) и Т-08 (события и агрегация). Пункт 3 также включает Т-05, который эта заготовка не закрывает. Это изолированный прототип на тестовых данных: он не подключён к приложению и не реализует реальную авторизацию. Выбор роли в демо не обеспечивает защиту данных.

## Как запустить на своём компьютере

Нужен Node.js с поддержкой `node:sqlite`: в нашей проверке использовался Node.js 26.13.0 в Windows. Новые npm-зависимости для демо не нужны. В терминале из корня отдельной копии репозитория:

```bash
git fetch origin
git switch test/stats-events
cd prototypes/role-statistics
node --version
node server.js
```

Откройте http://127.0.0.1:8090, выберите роль, нажимайте кнопки тестовых действий и переключайте роли. На Windows также можно открыть `start.cmd`. Для остановки нажмите Ctrl+C в терминале. Если порт 8090 занят, остановите программу, которая его использует, или согласуйте другой порт для демо.

Сервер слушает только свой компьютер. У каждого участника будет своя отдельная база в памяти; действия одного компьютера не появятся у других. После остановки сервера тестовые данные исчезают. Для совместной реальной работы нужно подключить общий сервер, настоящую аутентификацию и хранение — они пока не реализованы. Не используйте демо для настоящих личных данных и не открывайте его в интернет.

## Что внутри и что проверить

- `analytics.js` — отдельная SQLite-заготовка записи и подсчёта событий. `initialize` создаёт свою таблицу и индексы; это не согласованная миграция общего проекта.
- `StatisticsScreen.tsx` — компонент React Native для готового ответа сервера; запросы и проверка прав в него не встроены.
- `server.js`, `database.js`, `index.html` — локальный стенд с тестовыми ролями и событиями. `start.cmd` — запуск для Windows.
- `analytics.test.js` и `demo.test.js` — проверка счётчиков, границ периода, тестовых выборок и HTTP-стенда. Запустить: `node --test analytics.test.js demo.test.js`.

Счётчики: запросы подбора, подборы без результатов, открытия карточек, добавления в избранное, отметки «Нравится», запросы маршрута, нажатия «Поделиться». Категории (кафе, прогулка, событие) показывают количество открытий карточек с соответствующей категорией; список категорий тестовый. Кнопки «Поиск» и «Нет результатов» в стенде добавляют два отдельных события. В настоящем приложении владелец подбора должен согласовать, когда записывать каждый из них. Это количество событий, а не количество людей или текущее количество избранного. Нажатие «Поделиться» не доказывает успешную отправку. Повторная отправка считается новым событием; правила дедупликации и хранения не согласованы.

## Стыки для интегратора — предложения, не утверждённые API

1. **Т-01 / пункт 5:** после переноса старого приложения определить пути модулей, серверную авторизацию, миграцию и время хранения событий; согласовать контракт и идентификаторы.
2. Сервер получает роль и идентификатор пользователя из проверенной сессии. Для компании сервер сам получает список принадлежащих ей мест из авторитетного источника. Никогда не доверять роли, идентификатору пользователя или списку мест, присланным клиентом. Компонент экрана не является защитой.
3. В `analytics.js` вызовы `record` и `summarize` принимают **только данные, уже проверенные сервером**. Период задаётся UTC ISO-строками с миллисекундами; начало включено, конец исключён. Максимум 500 мест в тестовом фильтре компании; при большем каталоге нужно заменить способ выборки.
4. Владельцы экранов Т-02–Т-04 подключают согласованные события. При ошибке записи статистики основной сценарий должен продолжаться; не сохранять пароли, токены, поисковый текст, содержимое сообщений или точные координаты. Для пользовательских идентификаторов согласовать необходимость и срок хранения.
5. Т-07 подключает экран к защищённому серверному ответу после согласования интерфейса. Проверить, что администратор видит общие данные, компания — только принадлежащие ей места, пользователь — только свои действия; проверить пустую базу, ошибки и границы периода.
6. Пункт 5 интегрирует изменения, проводит сквозную проверку с настоящим приложением и записывает результат в `PROJECT_PROGRESS.md`.
